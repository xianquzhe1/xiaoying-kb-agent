# 04 AI 使用说明

这个项目基本是和 AI 一起完成的。下面写清楚哪些是 AI 做的，哪些是我做的，以及结果是怎么确认的。

## 用了什么

开发全程用 Claude Code（VS Code 插件）。

项目里 Agent 运行时调用的模型是 `claude-opus-5-5`，通过 Anthropic 官方 Python SDK（2.3.0）接入。请求经过一个兼容 Anthropic Messages API 的中转网关，地址通过 `ANTHROPIC_BASE_URL` 配置。

## AI 做了什么

大部分产出是 AI 写的：

- `src/` 下的全部代码，包括循环、工具、检索、模型适配和 CLI
- `data/` 里的 5 份合成制度和两份语料清单
- `tests/` 下的 41 个测试，以及 `scripts/run_cases.py`
- `examples/cases.json` 里的 10 个用例和期望
- README 和 docs/01–05 的初稿

`examples/runs/` 下的运行记录是脚本实际调用模型生成的，我没有手改过。`tests/test_recorded_runs.py` 会检查这些记录，如果被手工改动，这个测试会失败。

## 我做了什么

**选题。** 四道题我先自己看了一遍，倾向于前三题，然后让 AI 帮我做对比。最后选了题 3，主要有两个原因：

- 它需要的工具最少，时间可以花在决策循环本身。
- "引用是否属实"可以用代码直接校验，不用靠人判断。

题 1 我担心排期冲突的逻辑写出来会像规则引擎，题 2 的状态管理太重，3 小时内不好做扎实。

**决定用真实模型跑，不只交 Mock。** 题目写明了 Mock 不能证明决策效果，所以我准备了 API key 和网关地址。

**提交前让 AI 按考核规则和题 3 的要求逐条做了对照检查。** 这次检查发现文档里有几处和最终运行记录对不上，都已经改了：

- C2、C6 里写的检索词来自较早的一轮运行，和最终 trace 不一致。
- 02 里写循环"不到 200 行"，实际是 237 行。

代码我没有直接改过。开发中有三处调整是 AI 看了运行结果后做的：引用前必须先读原文、放宽 C8 的期望、新增 C10。原因和失败记录都写在 [03-evaluation.md](03-evaluation.md#失败记录) 里。

## 怎么验证的

1. 先用 Mock 把 10 个用例跑通，确认链路没问题，再换真实模型跑。
2. 不只看 PASS/FAIL。每个用例的 trace 都逐步核对过：每一步写的依据，是否对应上一步的返回结果。
3. C8 第一次判为 FAIL，但核对 trace 后发现模型的做法是合理的，问题出在期望写得太死。处理过程见 [03-evaluation.md](03-evaluation.md#c8-第一次运行期望写得太窄)。
4. 开发中发现并修了两个问题：
   - Mock 把"公司股票代码"答成了 answered。
   - 模型可以只看检索摘要就引用，不读原文。

   两处都补了测试。
5. 提交前检查了密钥：key 只写在本地 `.env`，`.gitignore` 已经把它排除。用 `git add -n` 预演过，`.env` 不会进入仓库。

## 用时

实际用时大约3个小时。

## 没做完的

- 每个用例只用真实模型跑了一次，没有多次采样来看稳定性。
- 没有在 Anthropic 官方 API 上直接重跑，只用过中转网关。
- 其他限制见 [03-evaluation.md](03-evaluation.md#已知限制)。
