# 01 需求

## 用户

公司员工。他们会问制度问题（报销、差旅、考勤）和产品问题（剪辑客户端 FAQ）。员工通常不知道答案在哪份文件里，用的词也和制度原文不一样，比如说"住酒店"而原文写的是"住宿费"。

## 目标

给出**有原文依据**的回答。员工要能据此行动，也能自己回到原文核对。

具体来说：

1. 能回答的问题，答案要附上文档 ID、版本日期和逐字引用的原文片段。
2. 资料之间有冲突时，把冲突摆出来，请用户确认适用哪份制度。不能替用户挑一个答案。
3. 资料里没有的内容，明确说没有，并说明缺了什么。不能编造。
4. 工具出故障时，如实说明没能取证，不能把猜测当作答案。

## 输入

- 用户问题（单轮），或问题加上对话历史（多轮追问）。
- 合成语料：5 份文档，每份带文档 ID、版本日期、负责部门，拆成若干片段（[data/docs/](../data/docs/)）。
  - D01《费用报销管理制度》2024-01-10，规定报销期限 30 天
  - D02《关于加快费用报销结算的补充通知》2025-03-01，规定报销期限 15 天，没有写明是否替代 D01
  - D03《差旅费用标准》、D04《考勤与假期管理制度》、D05《剪辑客户端常见问题FAQ》

D01 和 D02 的冲突是刻意设计的，对应题目参考实例。D02 没写"以本通知为准"或"原条款废止"，所以资料本身无法判定哪份优先。参考实例中"无冲突时可依据 D01 回答"，我构造的无冲突条件是从语料中移除 D02（[data/corpus_no_d02.json](../data/corpus_no_d02.json)）。

## 输出

| 字段 | 说明 |
|---|---|
| `status` | 任务状态，取值见 [README](../README.md#状态码) |
| `answer` | 回答正文 |
| `citations` | `[{doc_id, section_id, quote}]`，quote 必须逐字出自原文 |
| `gaps` | 资料缺口或需要用户确认的问题 |
| `trace` | 每一步的动作、参数、决策依据、返回摘要 |

## 范围

**做：**

- 原生 ReAct 循环，由真实模型（Claude Opus 5.5）决策
- 两个业务工具（检索、读原文）和一个结束动作（finish）
- 代码层的引用校验、步数上限、工具调用次数上限
- 故障注入，用来构造工具失败场景
- 离线 Mock 入口
- CLI 单轮问答和多轮对话

**不做：**

- 向量检索、Embedding、Rerank。语料只有 5 份，关键词检索够用，见 [02-solution.md](02-solution.md#检索为什么用关键词)
- Web 界面、线上部署、多 Agent、持久化会话
- 真实企业文档接入、权限控制

## 成功标准

题目列出 6 个必须验收的点。每个点至少有一个用例覆盖，用真实模型运行，结果写入 [examples/runs/anthropic/](../examples/runs/anthropic/)：

| 验收点 | 用例 | 判定方式 |
|---|---|---|
| 明确答案 | C1 | `status=answered`，引用 D04 |
| 文档冲突 | C2，并用 C3 对照 | C2 为 `conflict_needs_confirmation` 且同时引用 D01、D02；C3 去掉 D02 后为 `answered` 且只引用 D01 |
| 资料外问题 | C4 | `status=out_of_scope`，无引用 |
| 改写后的相似问题 | C5 | 口语化提问，`answered`，引用 D03 |
| 上下文追问 | C6 | "那一线城市呢？"，结合历史，引用 D03 |
| 工具失败 | C7、C8、C10 | 失败后能恢复的要答出来；持续失败的要返回 `tool_failed` 或在 gaps 中声明 |

另外两条硬性要求：

- 步数上限：C9 把 `max_steps` 设为 2，必须返回 `incomplete_step_limit`，不能把半成品包装成答案。
- 所有回答里的引用必须逐字出自原文。这条由代码校验（[agent.py](../src/kb_agent/agent.py) 的 `_validate_finish`），也由 [tests/test_recorded_runs.py](../tests/test_recorded_runs.py) 对已提交的记录再检查一遍。
